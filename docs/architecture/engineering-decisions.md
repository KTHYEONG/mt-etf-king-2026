## 2. Core Architecture Decisions

### ADR-01: Tournament Objective Function (Tail Optimization vs Sharpe Maximization)
* **Decision**: 전략 채택 및 승격 판정의 주 목적함수를 샤프 지수(Sharpe)나 평균-분산 최적화가 아닌, **36거래일 롤링 수익률 우측 꼬리 확률 $P(R_{36d} > \theta)$ 최적화 및 파산 제약($P(R_{36d} < -25\%) \le 5\%$)**으로 정의.
* **Why**: 대회 상금 구조는 순위에 따른 계단 함수(1위 1,000만 원, 2위 500만 원, 3위 이하 0원)입니다. 포트폴리오 변동성을 낮추고 샤프를 높이는 전통 분산 포트폴리오는 단기 36거래일 대회에서 우승 기대값이 0원에 수렴합니다. 2018~2026년 2,097개 롤링 윈도우에서 벤치마크 대비 우측 꼬리 확률을 극대화하면서도 파산 방지 하드 게이트(G2a)를 통해 회복 불가능한 손실을 원천 차단했습니다.
* **Trade-off**: 일별 변동성과 최대 낙폭(MDD)이 일반 자산배분 펀드 대비 커지므로, 장기 복리 운용이 아닌 단기 토너먼트 대회에 고도로 특화된 설계입니다.

### ADR-02: Next-Open Execution Protocol (Elimination of Look-Ahead Bias)
* **Decision**: 모든 전략 시그널은 $t$일 장 마감(15:30 KST) 종가로 산출하고, 체결 시뮬레이션은 **익일 개장 시가($t+1$ 09:00 KST Open)**에 호가 슬리피지(3~10 bps)와 거래 비용을 가산하여 집행.
* **Why**: 당일 종가에 시그널을 계산하고 동시에 종가에 체결시키는 Same-bar Fill 가정은 마감 직전 호가를 미리 알아야 하는 비현실적인 미래 참조 편향(Look-Ahead Bias)입니다. 장 마감 후 16:00에 자동 배치가 돌아 익일 장전 HTS 주문 가이드를 완성하는 실제 운영 프로세스와 백테스트를 1:1로 일치시켰습니다.
* **Trade-off**: 개장 직후 거래정지나 이상 시가 발생 시 체결 불가(Unfillable) 예외 처리가 필요합니다.

### ADR-03: Dual-Mode Universe Separation (Structural vs Deployment)
* **Decision**: 종목 유니버스를 연구용인 **`structural` 모드**와 실전 채택용인 **`deployment` 모드**로 분리하고, 전략 승격 판정은 오직 `deployment` 모드 결과로만 한정.
* **Why**: 과거 백테스트 시 현재 시점의 후원사 목록을 소급 적용하면 생존 편향이 발생하고, 반대로 전 종목을 허용하면 실전 모의투자 계좌에서 주문할 수 없는 유령 알파가 발생합니다. 팩터의 통계적 유효성은 시장 전체에서 확인하되, 최종 전략 승격 및 일일 주문은 실제 주문 가능한 종목군(대회 후원 10개 운용사 및 20일 ADV $\ge$ 1억 원)으로 엄격히 제한했습니다.
* **Trade-off**: 두 유니버스 패널을 각각 관리하고 검증해야 하므로 데이터 파이프라인 복잡도가 증가합니다.

### ADR-04: Post-Crash Anchor Sleeve for Tournament Regime Adaptation
* **Decision**: 60일 모멘텀 전략에 지수 급락 후 반등 구간 전용 앵커 슬리브를 결합한 **`sticky.mom60_post_crash_anchor`를 최종 챔피언으로 채택**.
* **Why**: 순수 60일 모멘텀은 평시 우수하지만, 코스피 지수가 급락한 직후 단기 급반등하는 국면(CRASH_REBOUND)에서 `mom60 < 0`으로 인해 전량 현금으로 철수하여 반등 기회를 놓치는 구조적 결함이 있었습니다. 급락 반등 진입 시 대표 지수 레버리지를 20일 모멘텀으로 앵커링하고 15% 하드 손절 가드로 방어하여, $P(R>30\%)$를 6.78%에서 **7.77%**로 개선하고 Worst 5% 손실(CVaR)도 -23.16%에서 **-21.56%**로 방어했습니다.
* **Trade-off**: 반등 실패 후 2차 급락 시 15% 손절 라인까지의 드로우다운을 감수해야 합니다.

### ADR-05: Parquet / Polars Columnar Storage vs Relational Database
* **Decision**: 데이터 저장소로 외부 RDBMS(PostgreSQL) 대신, **불변 Bronze gzip JSON (`.json.gz`)과 Silver/Gold In-Process Parquet + Polars 구조**를 채택.
* **Why**: 일별 1,100여 개 ETF의 8년치 데이터는 수백만 행 수준으로 분산 클러스터가 불필요하며, 외부 DB 데몬 설치 없이 `uv sync`만으로 단일 머신에서 즉시 재현 가능해야 합니다. Polars의 멀티스레드 컬럼너 지연 평가(LazyFrame)와 Zero-copy Arrow 메모리 구조를 활용하여 2,097개 롤링 백테스트를 수 초 이내에 완주합니다.
* **Trade-off**: 행 단위 실시간 OLTP 트랜잭션이 어려우므로, 일별 배치 증분 병합 방식을 사용합니다.

### ADR-06: Purged Walk-Forward GBDT Capacity Bound vs Deep Learning
* **Decision**: 머신러닝 적용 범위를 **단면 랭킹 전용 얕은 GBDT (LightGBM Ranker)**로 한정하고, 엄격한 트리 용량 상한(`max_depth=4`, `num_leaves=8`)과 Purged Walk-Forward CV를 강제.
* **Why**: 8년간의 일별 ETF 데이터는 총 행 수로는 수십만 건이지만, 36일 전방 수익률 라벨의 시계열 중첩과 높은 단면 상관으로 인해 실효 독립 표본 수($n_{\text{eff}}$)는 약 2,400개에 불과합니다. 이 규모에서 딥러닝이나 강화학습을 적용하면 시장 노이즈를 암기하여 심각한 과적합이 발생합니다.
* **Trade-off**: 비선형 복합 패턴이나 텍스트 등 비정형 데이터의 결합이 제한됩니다.

### ADR-07: Credential Management Pragmatism (.env vs SOPS/Age)
* **Decision**: 초기 검토했던 SOPS + Age 비대칭 인메모리 암호화 방식을 폐기하고, **`.gitignore` 기반 비추적 `.env` 파일과 `pydantic-settings` 표준 환경변수 주입 체계**로 간소화.
* **Why**: 단일 운영자 모의투자 시스템 환경에서 외부 암호화 바이너리(`sops`) 의존성과 개인키 배포 절차는 실보안 이득 대비 툴체인 복잡성을 불필요하게 가중시켰습니다. 저장소 비추적 표준 환경변수 관리만으로 보안 요구사항을 완벽히 충족합니다.
* **Trade-off**: 멀티 테넌트 팀 환경 확장 시 별도의 시크릿 공유 볼트가 필요합니다.

### ADR-08: Contest-Mode Rank-Objective Pivot (Weekly Simulation vs Daily Threshold)
* **Decision**: 실전 대회 라이브 의사결정을, 일일 임계값 최적화 챔피언에서 **약 1,200명 참가자 군중을 통계적으로 재현해 후보 종목별 $P(\text{rank}=1)$을 직접 추정하는 주간 순위 상대 시뮬레이터(`src/contest/`)**로 전환.
* **Why**: 대회 상금은 1~2위에게만 지급되므로 진짜 목적함수는 절대수익 임계치 초과가 아닌 순위표 상대 1위 확률입니다. 실측 결과 임계치 최적화 챔피언의 $P(\text{rank}=1)$은 1~5%에 그쳤고, 손절이나 비중 상한 등 변동성 축소 장치는 예외 없이 1위 확률을 절반 이하로 떨어뜨렸습니다. MT 순위표 불변 아카이브와 블록 부트스트랩을 결합하여, 현재 보유 대비 5%p 이상 우월할 때만 전환하는 히스테리시스(`switch_min_p1_gain`)를 두고 주간 최적 종목을 도출합니다.
* **Trade-off**: 주중 장중 반응이 없어 손실 위험을 그대로 감수하지만, 이는 1위 달성 확률을 극대화하기 위한 의도된 트레이드오프입니다.
